# Android 本地版

Android 7.0+，ARM64 手机。原生 WebView + Chaquopy 内置 Python，手机本地运行 FastAPI 和 SQLite；无需电脑、Node、MySQL、Redis 或 Termux。首次解压 Python，后续复用。手机号登录、浏览器 `/join` 授权都会把账号加入手机账号池。

API 默认 `http://127.0.0.1:8790/v1`，供同一手机上的 API 客户端使用。只有端口占用时选择新端口，启动成功后保存并复用。默认不向局域网暴露管理接口。应用自动进入工作台，后台接口和 `/v1` API Key 鉴权继续保留。

手机不显示或打包客户端参数页面、扫描本机及拆包工具，不安装桌面 SDK 或 Node；设备风控 SDK 不可用时沿用后端已有的无设备令牌路径，账号或上游需要额外风控时以实际返回为准。

## 授权与后台运行

手机号登录弹窗左下角“授权页面”打开系统浏览器中的本机 `/join`，支持短信或官方授权页面接力。浏览器完成授权后自动入库，返回应用刷新列表。这个 `127.0.0.1` 地址仅对本手机有效，不能分享给另一台设备。

服务用前台通知保持运行，离开界面或切到浏览器仍继续提供 API。通知里有“停止服务”，停止后再次打开应用即可启动。部分手机系统会限制后台运行，需要在手机的应用电池设置里允许后台活动。服务运行期间持有 CPU 唤醒锁以维持请求，会增加耗电；不使用时可停止服务。清除应用数据或卸载会删除账号与配置，覆盖安装同签名新版会保留。

数据位于应用私有目录 `files/WorkBuddy2API/`：`workbuddy.db`、`config.json` 和 `logs/mobile.log`。不会写入 APK 或公共存储目录，自动云备份关闭。

## 构建

使用 JDK 17、Gradle 8.11.1、Android SDK 35 和 Python 3.10：

```powershell
python scripts/build_android.py --gradle C:\Tools\gradle-8.11.1\bin\gradle.bat --jdk C:\Tools\jdk-17 --sdk C:\Tools\android-sdk
```

Gradle/Maven 优先使用阿里镜像，纯 Python 依赖使用清华镜像，Android 编译扩展由 Chaquopy 提供匹配架构的 wheels。全部运行依赖构建时装入 APK，不在手机上执行 pip 安装。

产物 `dist/android/WorkBuddy2API-版本-android-arm64.apk` 与 `.apk.sha256`。`build/android-signing/` 自动生成并保存本机签名密钥，必须自行备份此目录，后续覆盖更新使用同一密钥；不得提交到 Git。公开 APK 发布可使用现有 GitHub Releases，但构建时必须保留此签名身份。版本来源与桌面端共享 `desktop/version.json`。

`--prepare-only` 生成精简的 Python/静态资源目录，便于独立验证。不要把整个项目或本机 `.env` 当成 Chaquopy 的源目录。

## 模拟器验证

已在雷电 9（Android 9、WebView 91、ARM64 转译）验证免登录启动、手机号弹窗、系统浏览器打开 `/join`、浏览器切换后本地 API 继续运行。用已有账号实际调用 `/v1/chat/completions`，覆盖流式与非流式；测试账号和临时 Key 不写入发行 APK。未发送真实短信或执行新的账号授权。

端口回归测试让客户端保持连接，由服务主动关闭 TCP，再在同一进程连续重启，覆盖 `TIME_WAIT` 场景；只有活跃监听端口被其他服务占用才改用备用端口并保存。手机页面限制网格与卡片的最小宽度，长地址在卡片内换行，宽表格在自身容器中横滑；API 接入说明默认折叠，账号概览只在账号页显示。

复制地址使用 WebView 支持的选区复制命令，避免 `navigator.clipboard` 的权限拒绝；已实际读取模拟器系统剪贴板核对复制结果。

Android 的 TLS 证书上下文在启动时加载并复用；上游最多保留 4 条空闲连接，30 秒过期，减少连续调用的 DNS/TCP/TLS 开销。每个请求有独立的 Cookie 状态，关闭的连接由 HTTPX 丢弃，不自动重放 POST。手机对外 `/v1/` 接口在响应完整发送后明确关闭连接，避免第三方 Android 客户端复用失效的闲置连接；管理页继续使用长连接。这些策略仅在 APK 启用。外部 `/v1/models` 优先读本地模型配置；无配置时模型目录按凭证和上游缓存 5 分钟，冷查询缩短连接与读取超时，网络不通时不连续换号等待。本地模型启停与分组权限仍即时检查。

异步聊天中的数据库、凭证刷新和记账在工作线程执行，SQLite 写锁不会冻结事件循环；取消请求时等工作线程退出后再关闭会话。日志从聊天请求入口计时，流式首响应按实际转发增量统计（含思考或工具增量），首响应与最终答案出现时间不同。API 管理页的“调用诊断”记录最近 40 次外部调用的到达时间、首响应、总耗时及数据库/连接/TLS/上游等待等步骤，支持复制；只记录耗时，不收集 Key、凭证、请求或回答内容。

手机流式接口每 5 秒发送标准 SSE 注释心跳，避免长提示预处理或模型思考期间触发聊天客户端的无数据超时。心跳不会伪装成模型内容；诊断分开显示响应头、传输首字节、有效增量、当前处理时长和连接中断状态。终止事件在成功状态、记账和会话清理完成之后发送，兼容 Mirai 等收到结束帧就立即关闭连接的客户端。取消作用域内也会等待阻塞线程退出，避免残留名额或在数据库会话关闭后继续使用它。

本地 WebView 禁用 HTTP 缓存，覆盖安装后读取新版样式。全部依赖已内置，启动页仅显示本地服务启动状态。打包必须包含后端使用的 `converter.py`；运行测试从打包后的 staging 目录启动，防止源码目录掩盖漏打包模块。

诊断单独计时请求正文读取，并区分无效 JSON、编码错误与上传期间断开连接；原有 `bad json` HTTP 400 返回保持兼容。上传中断会记录为客户端断开，不能把读取失败后的快速错误响应当作整次调用很快。

APK 的 HTTP 协议层另外记录首个请求字节到处理器的等待、ASGI 调度等待和事件循环延迟；尚未到达协议层的网络等待与客户端收到响应后的处理仍无法从服务端计时。诊断记录上游请求次数、重试退避与安全的错误分类，不保留异常原文。流式连接收到完整正文之后监听客户端断开的等待，不计入上传耗时。

构建时加 `--with-debug` 可同时生成 `android/app/build/outputs/apk/debug/app-debug.apk`。调试包的应用 ID 带 `.debug`，数据与正式包隔离；只在调试包启用 WebView 调试和 `DebugProbeActivity`，用于通过 ADB 在真实嵌入式 Python 环境执行探针。调试入口不会进入正式 APK。
